# 阶段二 Day 1：AI 供应链安全 - 恶意模型投毒实战

## 一、攻击场景
- **目标**：AI 模型加载流程（torch.load）
- **攻击手法**：利用 Python Pickle 反序列化漏洞（`__reduce__` 魔术方法）。
- **攻击结果**：成功在受害者加载模型时执行任意系统命令（RCE），生成 /tmp/hacked_by_ai.txt。

## 二、防御与加固验证
- **修复方案**：使用 `torch.load(..., weights_only=True)` 限制只加载张量，或改用 `safetensors` 格式。
- **防御结果**：成功拦截，系统报错拒绝加载恶意对象。

## 三、审计视角与风险总结
- **风险**：在 AI 供应链中，开发者习惯从 HuggingFace 或网盘下载 `.pt`、`.pkl`、`.bin` 权重文件。如果未做安全校验直接加载，等同于运行未知的 `.exe` 病毒，直接导致服务器沦陷（参考《AI-Red 指南》第 8 章）。
- **建议**：
  1. 全面禁用 Pickle 格式的模型加载，强制切换到 SafeTensors。
  2. 在沙箱环境（如 Docker）中加载不可信模型。
  3. 对模型文件进行哈希校验，防止供应链投毒。

  特殊情况说明：在测试中，发现最新版 PyTorch (>=2.6) 默认启用了 weights_only=True 防护，成功拦截了恶意模型加载。
审计建议：虽然新版本默认安全，但必须排查企业生产环境中是否存在旧版本 PyTorch 的遗留系统；同时，必须敦促开发人员显式声明 weights_only=True，禁止使用任何使用 pickle 加载未知 .pt 文件的代码。
